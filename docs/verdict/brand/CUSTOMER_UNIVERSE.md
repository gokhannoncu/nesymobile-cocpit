## 0. TL;DR

| Gerçek | Yanlış okuma |
|---|---|
| ~**100 operasyonel logo** ≈ **80–85 ayrı satın alma merkezi** | 100 ayrı sözleşme |
| Sıra ≈ operasyon ölçeği (GMV / paket / gelir sinyali) | Birebir ciro sıralaması |
| Büyük ≠ kolay satılır (Amazon, Uber, Meituan kendi tech’ini yazar) | Mega logo = ilk müşteri |
| **Aras Digital / Nesy ölçekte altta, satış olasılığında #1** | Prestij listesinin tepesinden başla |
| Kamuya açık kurye app zorunlu değil | “Play Store’da app yok = hedef değil” |

**İlk beachhead:**

> Türkiye–Balkanlar–CEE hattında offline çalışan, scanner/printer/POS/fiscal kullanan Android kurye ve saha teslimat uygulamaları.

Doğru hedef tanımı:

> Şirketin kritik fiziksel operasyonunu yöneten bir **mobil yazılım yüzeyi** var mı ve kalite kararını şirket veya teknoloji tedarikçisi kontrol ediyor mu?

| 20 | $120K | **$2.4M** |

Bu dar evren tek başına Verdict’i **$5–15M ARR** bandına taşıyabilir. Sonraki genişleme: mobil POS, warehouse, field service.

## 5. Yazılım yüzeyi — Play Store şart değil

Önceki 100’ü “hepsinde kendi geliştirdikleri public Android kurye app var” diye okuma — **yanlış**.

### 5.1 Beş yüzey tipi

| Tip | Örnek / not |
|---|---|
| **1. Public courier/driver app** | Uber Driver, DoorDash Dasher, Amazon Flex, InPost Driver & Courier |
| **2. Internal saha APK** | Managed Play, MDM, Knox, Intune, sideload, enterprise store — Nesy bu sınıfa yakın |
| **3. El terminali yazılımı** | Zebra / Urovo / Honeywell / Datecs / Datalogic üzerinde rota, scan, POD, COD, offline, locker, printer/POS — UPS DIAD klasik örnek |
| **4. Üçüncü taraf last-mile** | Onfleet, Bringg, FarEye, DispatchTrack, Descartes, Manhattan, Oracle, SAP, yerel TMS — müşteri önce **yazılım sağlayıcısı** olabilir (1 entegrasyon → N lojistik firması) |
| **5. Taşeron uygulaması** | Marka sahibi platformu belirler; servis partneri yürütür; yazılım üreticisi app’i yazar — satın alma katmanı araştırılmalı |

### 5.2 POS zorunlu kriter değil

Tahsilat: nakit COD · fiziksel POS · SoftPOS · QR · link · prepaid · şirket hesabı · fiscal · hiç tahsilat yok.

Temel ihtiyaç:

```text
kritik transaction
+ fiziksel saha aksiyonu
+ local state
+ bağlantı kesintisi
+ backend sonucu
```

POS/fiscal varsa ACV yükselir (risk + doğrulama ihtiyacı).

### B — Uygun, teknik yapı önce doğrulanmalı

Posta idareleri · büyük 3PL · retail zincirleri · marketplace teslimat · depo/fulfillment · franchise/taşeron ağı.

Örn. DSV büyük ama linehaul/freight/depo ağırlıklı olabilir — UPS kadar doğal oturmayabilir.

Doğrulama soruları:

```text
Last-mile’ı kendisi mi yürütüyor?
Kendine ait field app var mı?
Mobil uygulamanın sahibi kim?
Android cihaz?
Offline?
Scanner / printer / tahsilat?
```

### C — Zayıf / dolaylı (TAM şişirmesi)

Tamamen dış kaynak · yalnız web portal · mobil kararı taşeronda · çoğunlukla linehaul/deniz/hava · saha transaction kritik değil.

**Tahmini filtre (100 logo):**

```text
50–60  doğrudan güçlü hedef
20–30  teknik yapı doğrulanacak
10–20  dolaylı / düşük uyum
```

## 7. ICP — qualification ve ideal profil

Sekiz sorudan **≥6 evet** → güçlü Verdict müşterisi:

| Soru | Ağırlık |
|---|---|
| Kurye / saha çalışanı mobil uygulama kullanıyor mu? | Kritik |
| Android / endüstriyel cihaz? | Yüksek |
| Barkod / scanner akışı? | Yüksek |
| Offline çalışma zorunlu mu? | Kritik |
| Local queue / persistence? | Kritik |
| Backend’de business transaction? | Kritik |
| POS / fiscal / printer peripheral? | Bonus |
| Hata maddi kayıp veya operasyon kesintisi yaratır mı? | Kritik |

**Ideal Customer Profile:**

```text
500+ aktif saha kullanıcısı
+ Android kurye uygulaması
+ günlük 10.000+ kritik işlem
+ offline çalışma
+ scanner / POD / COD
+ birden fazla cihaz veya ülke
+ release sonrası hata maliyeti yüksek
```

Bu profile giren küçük şirket, Uber’den daha iyi **ilk** müşteri olabilir.

## 9. Net sonuç

**Hayır** — listedeki 100 şirketin tamamında kamuya açık, kendilerine ait kurye uygulaması **olduğu iddia edilemez**.

Büyük last-mile / posta / yemek / market / saha şirketlerinin neredeyse tamamında şu üçünden biri vardır:

```text
kendi kurye uygulaması
veya kurumsal el terminali yazılımı
veya üçüncü taraf last-mile platformu
```

Satış araştırmasında ilk adım büyüklük değil — **operational mobile ownership**.

### Sonraki çalışma — yeniden tarama sütunları

```text
Courier app var mı?
Public / internal?
Android mi?
Cihaz markası?
Scanner?
POS / fiscal?
Offline?
App sahibi kim?
Satın alma merkezi kim?
Verdict uyumu?
```

Çıktı: prestij listesi değil — **gerçekten satılabilir 30–50 account’luk beachhead listesi**.
